# 本地批量脱敏规则验证台

一个完全运行在浏览器本地的脱敏规则调试工具：粘贴样本文本，配置一组**有序的正则规则**，实时查看脱敏结果、命中裁决解释与漏网敏感信息提示。支持**纯文本**与 **JSON 结构化**两种样例模式。数据只保存在浏览器 `localStorage`，不经过任何网络请求。

技术栈：React 18 + TypeScript + Vite。

## 一键启动（Docker Compose）

```bash
docker compose up -d --build
```

启动后访问：

> **http://localhost:8080**

停止：

```bash
docker compose down
```

> 端口可在 `docker-compose.yml` 的 `ports` 中修改（如 `"9000:80"`）。

## 本地开发 / Node 方式

要求 Node.js ≥ 18。

```bash
npm install
npm run dev
```

访问终端输出的地址（默认 **http://localhost:5173**）。

生产构建与本地预览：

```bash
npm run build      # 类型检查 + 输出到 dist/
npm run preview    # 预览构建产物，默认 http://localhost:4173
```

也可以直接用 Docker 构建镜像：

```bash
docker build -t mask-rule-bench .
docker run --rm -p 8080:80 mask-rule-bench
```

## 功能说明

### 有序正则规则

- 每条规则包含：名称、正则源码（不含 `//`）、标志位、替换模板、作用范围、颜色、启用开关。
- 规则按列表顺序确定优先级（`#1` 最高），可上下移动调整。
- 作用范围：
  - **全文匹配**：对整段文本执行一次匹配（配合 `m` 标志时 `^ $` 按行锚定，但匹配可跨行）；JSON 结构化模式下作用域为“单个字符串值整体”；
  - **逐行匹配**：对每一行独立执行，`^ $` 天然锚定单行，命中不会跨行。
- 标志中 `g` 由引擎强制开启；支持 `i m s u y`。
- 正则语法错误会就地提示，该规则自动跳过，不影响其他规则。

### 替换模板

- `$1` … `$99`：对应捕获组（未参与匹配的组替换为空串）；
- `$&`：整段命中文本；
- `$$`：字面量 `$`。

示例：`(\d{3})\d{4}(\d{4})` + `$1****$2` 可将 `13800138000` 脱敏为 `138****8000`。

### 匹配与重叠裁决（核心语义）

1. **所有启用规则先在原文上独立完成全部匹配**——规则之间互不可见，替换生成的内容不会再被任何规则扫描；
2. 全部命中按 **规则优先级（列表序号）→ 起始位置（靠前优先）→ 结束位置（靠长优先）** 排序；
3. 依次领取字符区间：与已采用命中区间重叠（含相同起始位置、零宽冲突）者一律**舍弃**，并记录舍弃原因（与谁重叠、对方归属哪条规则）；
4. 最后对采用命中做**一次性替换**并拼接结果。

因此「高优先级规则的替换产物里恰好包含低优先级规则的样式」绝不会造成二次脱敏。

### JSON 结构化模式

每个样例可在样例栏切换「纯文本 / JSON 结构化」两种模式，模式随样例一起持久化；旧配置与旧导入文件中没有模式字段的样例，一律按**纯文本**处理。

在 JSON 结构化模式下：

1. 原文先被解析为 JSON；**解析失败时不生成任何脱敏结果**，界面直接显示错误所在的**行、列（1 起始）与字符偏移**；
2. 只对**对象与数组中的字符串值**（根节点本身是字符串时同样处理）分别独立运行全部规则；
3. **键名、数字、布尔值和 `null` 原样保留**——数字中的手机号样式、键名中的敏感词都不会被匹配或改写，数字也按原文切片保留（不做 `1.00 → 1` 之类的规范化）；
4. **禁止跨字段匹配**：每个字符串值都是独立的匹配输入，即使两个值在序列化文本中相邻，规则也不可能跨越键名、标点或另一个字段命中；
5. 单个值内部仍沿用全部现有语义：规则优先级、起始/结束位置排序、重叠（含零宽）裁决、一次性替换、生成物不再参与扫描；
6. 脱敏结果以**格式化 JSON（2 空格缩进）**展示，字符串内的引号、换行等转义会正确重新序列化，输出可直接再次 `JSON.parse`；
7. 「命中解释」按字段的 **RFC 6901 JSON Pointer** 分组（如 `/contact/phone`、`/logs/0`），根字符串的 Pointer 为空串；指针中的 `~` 转义为 `~0`、`/` 转义为 `~1`（键名 `a/b~c` → `/a~1b~0c`），解释中同时给出字段在原文中的位置与命中在**值内**的行列；
8. 「未覆盖检查」同样按值独立进行，每条提示附带所属字段的 Pointer。

> 重复键是合法 JSON（后写覆盖先写），它们的 Pointer 相同；界面对每个字符串节点独立分析并分别展示。

### 联动高亮与命中解释

- 原文与脱敏结果上下对照：实色下划线 = 采用命中，波浪虚框 = 舍弃命中，黄色底纹 = 未覆盖的疑似敏感信息。
- 在原文、结果、解释列表、未覆盖列表任一处悬停/点击，其余视图同步高亮；点击解释条目会自动切回对照视图并滚动定位。
- 「命中解释」按规则分组，逐条给出采用/舍弃标签、命中文本、行列位置、捕获组取值、替换结果或舍弃原因。

### 未覆盖敏感信息提示

内置启发式检测（仅提示，不自动替换）：

- **邮箱**：`name@domain.tld` 样式；
- **手机号**：`1[3-9]` 开头的 11 位数字（带数字边界）；
- **身份证**：18 位样式，校验出生日期合法性，并按 GB 11643 验算末位校验码（通过/不通过都会标注）。

只有完全落在某个「采用」命中区间内的候选才算已覆盖；落在「舍弃」命中上的依然报警。身份证候选内部包含的手机号样式会自动抑制，避免重复计数。

### 持久化与导入导出

- 规则、样例（含当前选中项与每个样例的「纯文本 / JSON 结构化」模式）自动保存到浏览器 `localStorage`；
- 顶栏「导出 JSON」下载完整配置；「导入 JSON」选择文件后替换当前配置（有确认提示）；旧文件缺少模式字段时默认纯文本；
- 「恢复默认」可回到内置演示规则与样例。

导出文件结构：

```json
{
  "rules": [
    {
      "id": "rule-xxx",
      "name": "手机号（保留前3后2）",
      "enabled": true,
      "pattern": "(?<!\\d)(1[3-8]\\d)\\d{6}(\\d{2})(?!\\d)",
      "flags": "g",
      "template": "$1******$2",
      "scope": "all",
      "color": "#d97706"
    }
  ],
  "samples": [
    {
      "id": "sample-xxx",
      "name": "样例名",
      "text": "样本文本",
      "mode": "text"
    }
  ],
  "currentSampleId": "sample-xxx"
}
```

`scope` 取值为 `all`（全文）或 `line`（逐行）。`mode` 取值为 `text`（纯文本，缺省默认）或 `json`（JSON 结构化）。

## 说明与边界

- 本工具面向**规则调试与验证**，内置的邮箱/手机/身份证检测是启发式提示，并非穷举识别（例如运营商新号段、带分隔符的写法不会被覆盖检测发现），生产识别请自行在规则中补齐。
- 所有计算均在浏览器本地完成，不上报任何文本内容；清空浏览器站点数据等同于删除配置。
